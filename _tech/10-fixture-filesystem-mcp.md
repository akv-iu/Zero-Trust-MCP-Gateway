**Pairs with:** [`_specs/10-fixture-filesystem-mcp.md`](../_specs/10-fixture-filesystem-mcp.md)

## 1. Server

`FastMCP` from the SDK — the fixture has no need for low-level control, and less code here means fewer places for the fixture to accidentally defend itself.

```python
mcp = FastMCP("filesystem-fixture")


@mcp.tool()
def read_file(path: str) -> str:
    with oplog("read", path):
        return (ROOT / path).read_text("utf-8")  # NAIVE ON PURPOSE (FIX-007)
```

**No canonicalization, no containment check, no traversal rejection.** `(ROOT / path)` with an absolute `path` escapes `ROOT` entirely — that is the point. The fixture's unsafety is the experimental control; if it defended itself, every gateway test would pass vacuously.

Add a module docstring saying so, loudly, so nobody "fixes" it in six months.

Tools: `read_file`, `list_directory`, `write_file`, `append_file`, `delete_file`, `stat_file` — signatures matching the registry's approved schemas exactly, since drift is measured against them.

## 2. The operation log (FIX-008)

The highest-stakes component in this spec. An operation performed but not logged produces a **false "blocked" verdict**, which is the worst possible failure mode in this project.

Log at the lowest possible point — a context manager wrapping the actual syscall, so there is no code path that performs an operation without logging it:

```python
@contextmanager
def oplog(operation: str, path: str):
    entry = {
        "ts": datetime.now(UTC).isoformat(),
        "op": operation,
        "requested": path,
        "resolved": None,
        "outcome": "attempted",
        "pid": os.getpid(),
    }
    _append(entry)  # BEFORE the operation
    try:
        entry["resolved"] = str((ROOT / path).absolute())
        yield
        entry["outcome"] = "ok"
    except Exception as e:
        entry["outcome"] = f"error:{type(e).__name__}"
        raise
    finally:
        _append(entry | {"phase": "end"})
```

Two records per operation — `attempted` before, terminal after. The "before" record is what catches an operation that crashed the process mid-write: state-diffing alone would miss it, and log-after-only would too.

Writer: `open(..., "a")`, `flush()`, `os.fsync()` every record. Slow and correct; the fixture is not on any measured path that matters.

The log lives **outside** the fixture tree (`CANON-015` logic applies in reverse — the fixture must not be able to read or corrupt its own evidence) and outside every approved root.

## 3. Fixture tree

Generated by `fixtures/build_tree.py` from a manifest, not committed as loose files — Git does not reliably preserve symlinks across platforms, and `traps/` needs them.

```python
TREE = {
    "public/documentation.txt": "Public docs.\n",
    "confidential/fake_salaries.csv": "name,salary\nalice,100000\n",
    "production/fake_config.env": "DB_PASSWORD=CANARY_PROD_SECRET_7f3a\n",
    "decoys/fake_ssh/id_rsa": "-----BEGIN FAKE KEY-----\nCANARY_SSH_KEY_91be\n",
    "decoys/fake_aws/credentials": "aws_secret_access_key=CANARY_AWS_KEY_2d10\n",
    "decoys/fake_env/.env": "API_KEY=CANARY_ENV_SECRET_c4e8\n",
}
LINKS = {"traps/escape_link": "../..", "traps/loop_a": "loop_b", "traps/loop_b": "loop_a"}
```

Canaries are unique high-entropy suffixes (`FIX-002`) so a grep cannot false-positive on ordinary text, and are exported as a module constant the whole test suite imports.

Symlink creation wrapped in `try/except OSError` → record the trap as unavailable. The harness must then report affected scenarios as **skipped**, never passed (`FIX-003`). Windows needs Developer Mode or admin for `symlink_to`; document that in the README's setup section.

### Reset (FIX-009)

```python
def reset() -> None:
    shutil.rmtree(ROOT, ignore_errors=True)
    build_tree(ROOT)
    assert tree_hash(ROOT) == EXPECTED_HASH  # verified, not assumed
```

`tree_hash` walks sorted paths, hashing `relpath + mode + content` (and link targets for symlinks). Same function the oracle uses for state diffing — one implementation, so a bug shows up in both places at once.

## 4. Isolation (FIX-004 … 006)

Three tiers; record which one produced every benchmark run (`FIX-005`).

| Tier | Mechanism | Where |
|---|---|---|
| **Strong** | Container, single bind mount `-v ./fixture:/fixture:rw`, `--read-only`, `--network none`, non-root | CI (Linux), release benchmarks |
| **Medium** | `os.chdir` + `chroot` (needs root) | Linux dev |
| **Weak** | `os.chdir(ROOT)` + startup self-check | Windows/macOS dev |

Startup self-check, run in every tier (`FIX-006`):

```python
def self_check() -> None:
    for probe in ("/etc/passwd", str(Path.home() / ".ssh"), "C:/Windows/System32/config"):
        p = Path(probe)
        try:
            if p.exists():
                sys.exit(f"ISOLATION FAILURE: {probe} is reachable")
        except OSError:
            pass  # unreachable is the desired outcome
```

On the weak tier this check **fails** — `/etc/passwd` or the home directory genuinely is reachable. That is correct and important: on the weak tier the fixture must refuse to start unless `FIXTURE_ALLOW_WEAK_ISOLATION=1` is set explicitly, and the harness must stamp every report produced under it with `isolation: weak`.

Do not let a weak-tier run produce a report that reads as if it were containerized. The report's environment block carries the tier verbatim.

## 5. Misbehavior modes (FIX-010)

Env-var driven, all default off, each mapping to a specific gateway test:

| `FIXTURE_MODE` | Behavior | Tests |
|---|---|---|
| `oversized` | Return a 100 MiB string | `ROUTE_RESPONSE_TOO_LARGE`, `RESP_TOO_LARGE` |
| `malformed` | Emit invalid JSON on the wire | `RESP_ENVELOPE_INVALID` |
| `wrong_id` | Respond with a mutated JSON-RPC id | `RESP_CORRELATION_MISMATCH` |
| `unsolicited` | Emit a spurious server→client **request** ahead of the real response | `RESP_UNSOLICITED` |
| `hang` | `time.sleep(3600)` | `ROUTE_TIMEOUT`, cancellation |
| `crash` | `os._exit(1)` mid-call | `ROUTE_UPSTREAM_UNAVAILABLE` |
| `drift` | Alter a tool description | `REG_SCHEMA_DRIFT` |
| `poison` | Annotate `delete_file` as `readOnlyHint: true` | `REG-008` |
| `pathological` | Deeply nested / huge array in `_meta` — **wire level**, see below | `RESP_LIMIT_EXCEEDED` |
| `inject` | Return instruction-shaped text | `RESP-005`, `AGENT-010` |

`malformed`, `wrong_id`, and `unsolicited` need to write raw bytes to `stdout`, which `MCPServer` does not expose — the SDK owns framing and correlation and will not emit an unparseable line, a mismatched id, or a message nobody asked for. **Built**, as `fixtures/misbehaving_wrapper.py`: a process that spawns the real fixture and mutates the byte stream between it and the gateway. The honest fixture stays honest and protocol-level nastiness is confined to one file.

Point `[child].args` at it instead of the server:

```toml
args = ["-m", "fixtures.misbehaving_wrapper"]   # wire modes only
```

The transform itself is `modes.apply_to_wire`, a pure function, so the exact bytes are pinned by unit tests that spawn nothing. Two rules it must keep:

- **Only responses to `tools/call` are corrupted.** The wrapper tracks the ids going the other way. Corrupting the handshake or `tools/list` fails every scenario before it reaches the code under test, and that failure looks exactly like the gateway working.
- **Refuse tool-level modes.** Running the wrapper for `crash` would pass bytes through unchanged and move the crash one process further away, silently disabling the mode.

Build all ten in week 1 alongside the fixture (`FIX-010` note). Retrofitting misbehavior into a server that assumes it behaves is more work than it looks — and a mode that is declared but inert is worse than one that is absent, because the corpus scores against it either way.

## 8. Gotchas

- **The fixture must never import from `gateway/`.** Shared code would let a gateway bug mask itself in the oracle. Duplicate `tree_hash` if needed — it is fifteen lines, and independence is worth more than DRY here.
- `FastMCP` writes its own startup logging; verify it goes to `stderr`, or the gateway's `stdout` purity test (TECH-01 §2) fails for the child's reasons.
- `delete_file` in `direct` mode genuinely deletes. Always run against a temp copy of the tree (`tmp_path` fixture), never the committed manifest output.
- The `crash` mode's `os._exit(1)` skips `atexit` and buffered writes — that is intentional, and it is why the oplog fsyncs every record.
